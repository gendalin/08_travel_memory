# Preprocessing Spec — Tokyo Demo

Working reference for the pipeline. The authoritative setup instructions are in
[`preprocessing_setup_spec.md`](./preprocessing_setup_spec.md); the output shapes
are in [`demo_data_contract.md`](./demo_data_contract.md).

---

## Boundary

```text
source_inputs/
    ↓
scripts/preprocess/
    ↓
data/demo_tokyo_v1/
    ↓
product
```

Application code under `/src` must never import or read `source_inputs/`.
The product reads only `data/demo_tokyo_v1/`.

---

## Raw sources are immutable

Preprocessing may read, parse, extract metadata and generate derived files.

It must never:

- rename original source files
- overwrite original source files
- modify EXIF metadata
- compress originals
- delete originals

## Pipeline stages

| Stage | Script | Reads | Produces |
| --- | --- | --- | --- |
| 1 | `preprocess/extract_photo_metadata.ts` | `photos/` | `PhotoMetadata[]` (in memory) |
| 2 | `preprocess/normalize_map_links.ts` | `maps/map_links.csv` | `NormalizedMapLink[]` (in memory) |
| 3 | `preprocess/normalize_screenshots.ts` | `screenshots/` | `ScreenshotRecord[]` (in memory) |
| 4 | `preprocess/build_evidence.ts` | stages 1–3 | `evidence.json` |
| 5 | `preprocess/build_candidate_memories.ts` | `evidence.json` | `memories.json` |
| 6 | `preprocess/build_user_context.ts` | `evidence.json` | `user_context.json` |
| 7 | `preprocess/build_tokyo_demo_bundle.ts` | all of the above | orchestration + `manifest.json` |
| — | `validate_demo_data.ts` | `data/demo_tokyo_v1/` | pass / fail report |

`tokyo_places.json` is curated separately (80–150 POIs) and is not regenerated by
the pipeline. `demo_scenario.json` events stay unbound until those places exist.

Shared types and paths live in [`../scripts/preprocess/types.ts`](../scripts/preprocess/types.ts).

## Inference rules

**Photos** may support evidence for travel pace, typical daily start time,
movement pattern, spatial range, number of stops, and repeated destination
categories. A photographed subject is not automatically a stable preference.

**Map links** represent intentional saves. One saved place is weak evidence;
repeated categories are stronger. A saved place is not a confirmed preference.

**Screenshots** represent intentionally saved information and possible interest.
A screenshot never implies a visit, and stays a separate evidence kind from
travel photos.

**Never infer** identity of people, personal relationships, or sensitive traits.

---

## Memory rule

Preprocessing produces `candidate` memories only. It must never create active
memory — activation is a product-runtime decision.

- `status` is always `"candidate"`
- `confidence` is independent from `status`
- every memory carries provenance with at least one valid evidence id

---

## Commands

```bash
npm run preprocess:tokyo   # raw sources -> data/demo_tokyo_v1/
npm run validate:data      # validate data/demo_tokyo_v1/
```

`preprocess:tokyo` refuses to run against an empty source set, so a real bundle
is never silently replaced with an empty one.
